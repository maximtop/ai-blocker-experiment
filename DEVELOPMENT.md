## Prerequisites

### Required Tools

This workspace was verified with:

- Node.js `v25.9.0`
- pnpm `10.33.4`
- npm `11.12.1`
- Chrome or Chrome Canary that can load Manifest V3 unpacked extensions

The project uses pnpm. Prefer `pnpm` and `make` commands over npm commands so
the lockfile and scripts stay consistent.

### Browser Requirements

- The extension manifest currently requires Chrome `149` or newer.
- Chrome Canary 149+ is recommended for HTML-in-Canvas screenshot testing.
- Enable `chrome://flags/#canvas-draw-element` before testing
  HTML-in-Canvas screenshots on arbitrary pages.
- For local `file://` test pages, Chrome requires explicit "Allow access to
  file URLs" permission on the unpacked extension details page.

## Getting Started

### Install Dependencies

From the repository root:

```sh
make init
```

Equivalent command:

```sh
pnpm install
```

### Build The Extension

```sh
make build
```

Equivalent command:

```sh
pnpm build
```

This writes the unpacked extension to `dist/` and creates
`dist/extension.zip`.

### Load The Extension Locally

1. Build the extension with `make build`.
2. Open `chrome://extensions/`.
3. Enable **Developer mode**.
4. Click **Load unpacked**.
5. Select the repository `dist/` directory.
6. Reload the extension from `chrome://extensions/` after each rebuild.

Chrome's official unpacked-extension flow is documented in the Chrome
Extensions getting started guide.

### Enable Local File Testing

To test `test-page/*.html` with `file://` URLs:

1. Open `chrome://extensions/`.
2. Find the loaded AI Ad Blocker extension.
3. Open **Details**.
4. Enable **Allow access to file URLs**.
5. Open a local test page such as `test-page/visual-test.html`.

## Development Workflow

### Recommended Loop

1. Read `AGENTS.md` before editing code.
2. Make a focused change.
3. Add or update tests under `tests/<area>/`.
4. Run the focused Vitest command for the touched area.
5. Run `pnpm lint`.
6. Run `pnpm test`.
7. Run `make build` when manifest, bundle, UI, or extension context code
   changed.
8. Reload the unpacked extension in Chrome and perform any needed manual check.

### Code Checks

Run lint and type checking:

```sh
pnpm lint
```

Run TypeScript only:

```sh
pnpm type-check
```

There is no configured formatter command. Keep formatting consistent with the
existing four-space indentation and AGENTS.md Markdown rules.

### Testing

Run the full test suite:

```sh
pnpm test
```

Run one test file:

```sh
pnpm test tests/content/auto-screenshot-observer.test.ts
```

Vitest runs in Node environment. Mock Chrome APIs and browser-specific objects
inside tests instead of requiring a real browser.

### Build Output

Do not edit `dist/` manually. It is generated by Rollup and the copy plugin.

`rollup.config.js` builds these bundles:

- `dist/background.js`
- `dist/content/content.js`
- `dist/popup/popup.js`
- `dist/options/entry.js`
- `dist/offscreen/offscreen.js`

It also copies static HTML files, icons, locales, and `manifest.json`. The
manifest version is injected from `package.json`.

## Development Commands

### Make Targets

| Command | Purpose |
| --- | --- |
| `make init` | Install pnpm dependencies. |
| `make build` | Build `dist/` and package `extension.zip`. |
| `make lint` | Run ESLint and TypeScript checks. |
| `make test` | Run the Vitest suite. |

### Package Scripts

| Command | Purpose |
| --- | --- |
| `pnpm build` | Run Rollup build. |
| `pnpm postbuild` | Zip `dist/` into `extension.zip`. |
| `pnpm clean` | Remove `dist/`. |
| `pnpm dev` | Run clean plus build watch. See note below. |
| `pnpm lint` | Run ESLint, then `pnpm type-check`. |
| `pnpm type-check` | Run `tsc --noEmit`. |
| `pnpm test` | Run `vitest run`. |

`pnpm dev` currently references `pnpm build:watch`, but `build:watch` is not
defined in `package.json`. Use `pnpm build` or add the missing script before
relying on watch mode.

## Common Tasks

### Test A Local Page

1. Run `make build`.
2. Load or reload `dist/` in `chrome://extensions/`.
3. Enable file URL access for the extension.
4. Open `test-page/index.html` or `test-page/visual-test.html`.
5. Use the popup to add or test rules.
6. Use DevTools on the page for content-script logs.

### Use HTML-in-Canvas Screenshots

1. Use Chrome Canary 149 or newer.
2. Enable `chrome://flags/#canvas-draw-element`.
3. Restart Chrome.
4. Build and reload the extension.
5. Open options and confirm **Use HTML-in-Canvas element screenshots** is on.
6. Test a `:contains-meaning-vision(...)` rule on `test-page/visual-test.html`.

If screenshots are empty or fail, inspect content-script logs first. The
renderer runs in the content script and sends pre-rendered data URLs to the
background for vision analysis.

### Use Local LM Studio Models

LM Studio integration expects a server at:

```text
http://localhost:1234
```

The code calls:

- `http://localhost:1234/v1/models`
- `http://localhost:1234/v1/embeddings`
- `http://localhost:1234/v1/chat/completions`

Start LM Studio's local server before selecting LM Studio models in extension
settings.

### Use Cloud Models

Open extension options and add API keys through the UI:

- OpenAI API key for OpenAI models.
- OpenRouter API key for OpenRouter models.

Do not put API keys in source files, environment files, or commits. The
extension stores keys in `chrome.storage.local`.

### Debug Extension Contexts

- **Background service worker**: open `chrome://extensions/`, find the
  extension, and inspect the service worker.
- **Content script**: open DevTools on the target page.
- **Popup**: right-click the popup and inspect it while open.
- **Options page**: open the extension options page and use normal DevTools.
- **Offscreen document**: inspect via extension internals when diagnosing
  screenshot cropping or canvas work.

Use logger context prefixes to identify the module producing each message.

### Update Documentation

- Update `README.md` for user-facing setup, requirements, and usage changes.
- Update `CHANGELOG.md` for user-visible behavior or compatibility changes.
- Update `AGENTS.md` when code structure or agent rules change.
- Update this file when setup, commands, local workflows, or troubleshooting

## Troubleshooting

### Build Fails

Run:

```sh
pnpm lint
pnpm test
```

Fix TypeScript and ESLint errors before rebuilding. If generated output looks
stale, run:

```sh
pnpm clean
make build
```

### Extension Does Not Load

- Confirm `dist/manifest.json` exists.
- Confirm Chrome is version 149 or newer.
- Confirm you selected `dist/`, not the repository root.
- Rebuild with `make build`, then reload the extension.

### Local File Pages Do Not Work

Enable **Allow access to file URLs** on the extension details page. Chrome does
not grant `file://` page access automatically.

### HTML-in-Canvas Screenshots Fail

- Use Chrome Canary 149+.
- Enable `chrome://flags/#canvas-draw-element`.
- Restart Chrome after changing the flag.
- Confirm the option checkbox is enabled.
- Check page DevTools for `HtmlInCanvasScreenshotService` and
  `AutoScreenshotObserver` logs.
- Some cross-origin, unsupported, or not-yet-loaded content may be omitted by
  Chrome's HTML-in-Canvas rendering path.

### LM Studio Models Are Unavailable

- Start the LM Studio server.
- Confirm `http://localhost:1234/v1/models` responds.
- Select LM Studio models again in extension settings.
- Check background service worker logs for provider errors.

### Lint Shows npm Config Warnings

`pnpm lint` can print npm warnings about unknown config keys before running
ESLint and TypeScript. Treat those warnings as environment noise if the command
exits successfully.
